## 2. Schema & migration

- Schema: `ProductStatus += HIDDEN`; new `VariationType` enum; Product/Reference/OrderItem additive nullable columns; new `ProductAttribute` table (gated by `isProductAttribute` in service, Phase 5); `PackItem.productReferenceId` FK **SetNull → Restrict** (closes R13).
- Structural migration generated by `prisma migrate dev` and **applied**. SQL matches the Phase 3 design exactly (additive columns, indexes, `product_attributes`, FK hardening).
- Backfill migration hand-written (`...180500_product_domain_backfill`): order-snapshot enrichment + `ACTIVE`+`isActive=false` → `HIDDEN` reconciliation. **Not yet applied** — it mutates data and needs explicit approval (`prisma migrate deploy`).

## 3. Field-visibility enforced (Phase 2 §7)

- **Public** product: adds `productType`, content fields, `compareAtPrice`, derived `priceFrom`/`onSale`/`percentageSaving`; references add shade fields + `effectivePrice` + derived `inStock`/`lowStock`. `costPrice`, `reservedQuantity`, `lowStockThreshold`, raw scoring stay hidden.
- **Compat window (C10):** `status` and exact `stockQuantity` are still physically present in the public payload for now; their removal is deferred to Phase 8 after the frontend migrates to the derived signals (additive-first, R15).
